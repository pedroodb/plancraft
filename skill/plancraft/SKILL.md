# Plancraft — Architectural Floor Plan Generator

Plancraft is a code-driven tool for generating precise, AutoCAD-like architectural floor plans. You write `.pc` files using a compact, indentation-based DSL, then compile them to SVG. Furniture is managed separately in `.pcf` files.

## Two-Phase Workflow

Floor plan creation is split into two independent phases:

### Phase 1: Structure (walls, doors, windows, stairs)

Get the building skeleton right first. This is the critical phase — all room boundaries, door placements, window positions, and staircase locations must be accurate before proceeding.

**Guide**: `rules/structure-guide.md`

```bash
plancraft compile plan.pc --structure-only -o plan-structure.svg
```

### Phase 2: Furniture (interior layout)

Once the structure is verified, add furniture and fixtures to each room using the furniture placement system. Furniture placements are stored in a separate `.pcf` file.

**Guide**: `rules/furniture-guide.md`

```bash
plancraft compile plan.pc --furniture plan.pcf -o plan.svg
```

## Key Concepts

- **File format is a compact DSL** with indentation-based structure and `//` comments
- **Communicate measurements in meters** to users; internal .pc format uses millimeters (multiply by 1000)
- **Coordinates are compact pairs** `x,y` (e.g. `5000,0`)
- **Walls are defined by start/end points** with explicit thickness
- **Wall direction names** can be cardinal directions (`north`, `east`, `south`, `west`) or custom strings (`"east lower"`)
- **Curved walls** use the optional `bulge=N` property — negative curves outward (CW), positive curves inward (CCW), `1.0` = semicircle. See `walls.md`
- **Diagonal/oblique walls** are created by setting non-axis-aligned from/to coordinates
- **Doors and windows reference walls** by direction name
- **Openings** create wall gaps without door panels (archways, open-plan transitions)
- **Sliding doors** use `sliding` swing type
- **Furniture** is stored in a separate `.pcf` file, referencing SVG elements from packages
- **Custom furniture elements** can be defined inline in the `.pcf` file with SVG, tags, and dimensions
- **Shared walls** avoid duplicate geometry between adjacent rooms
- **Labels and dimensions** are auto-generated by the renderer (not part of the .pc file)
- **Structure**: `plan:` > `floor:` > `room:` > walls/doors/windows/openings

## Furniture System

Furniture elements are individual SVG files organized into packages:
- **default** — Standard furniture (bed, sofa, table, toilet, etc.)
- **modern-living** — Contemporary living room pieces
- **office** — Workspace furniture

Elements are referenced as `package/element` (e.g. `default/bed`). Placements support three positioning methods:
- **`at x,y`** — Absolute mm coordinates (traditional)
- **`anchor <wall> <along> <offset>`** — Wall-aligned positioning. The system auto-computes the exact position including wall thickness. **Recommended for wall-adjacent items** (beds, wardrobes, toilets).
- **`rel x,y`** — Percentage within room bounding box (0-1). **Recommended for center-of-room items** (tables, rugs).

**Always call `get_room_geometry` first** to get room bounds and wall positions before placing furniture. Check spatial validation warnings from tool responses.

See `rules/furniture.md` for the complete element reference and `.pcf` format.

## Minimal Example

Structure (.pc file):
```
plan: "Studio"

floor: "Ground Floor"
  room: "Main Room"
    wall north 0,0 5000,0 200
    wall east 5000,0 5000,4000 200
    wall south 5000,4000 0,4000 200
    wall west 0,4000 0,0 200
    door north 1500 900 left
    window east 1000 1200 1400 900
```

Furniture (.pcf file):
```
furniture:

placements:
  place default/sofa at 2500,2000 in "Main Room"
```

## Limitations and Workarounds

Some architectural elements cannot be directly represented. When you encounter these, use the closest available approximation and add a `//` comment documenting what's missing.

| Element | Workaround |
|---------|-----------|
| Round columns / pillars | Not supported; add a `// NOTE: column at (x, y) diameter Nmm` comment |
| Fixtures not in element list | Use the closest element or create a custom SVG element with `create_furniture_element`; add a `// NOTE:` comment describing the actual fixture |
| Multi-floor stair connections | Use `default/staircase` or `default/spiral_staircase` on each floor; floors are not linked |
| Balconies / outdoor spaces | Define as a room with thinner walls; add a `// NOTE: outdoor/balcony` comment |

**Note**: Curved walls and diagonal walls ARE supported natively — see `walls.md` for `bulge` syntax and diagonal wall coordinates.

**Always** document unsupported elements rather than silently omitting them. This lets users know what needs manual adjustment.
